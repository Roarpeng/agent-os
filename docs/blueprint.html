1. 核心思想

不是让 Agent 写更多，而是让 Agent 选择更好的完成方式。

01 · Think

先理解，再行动

先读上下文、确认目标和约束；不要看到问题就猜测和修改。

02 · Medium

先选输出媒介

Text → Table → Diagram/SVG → HTML。复杂关系优先可视化。

03 · Verify

执行后验证

代码、方案、研究结果都尽可能验证。不要把“看起来正确”当成完成。

3. 核心 AGENTS.md

这是唯一建议长期常驻的全局规则。控制在极短范围。

# Agent OS

- 先理解目标，再行动；先读/验证，再猜测/修改。
- 简单任务直接完成；复杂任务先计划。
- 选择最有效的输出：Text → Table → Diagram/SVG → HTML。
- 技术解释使用短句、明确术语、低歧义；必要时采用 70–80% ASD-STE100 风格。
- 能直接构建工具、Demo、可视化或 HTML，就不要只描述做法。
- 优先复用现有代码和工具，避免无关重构。
- 修改遵循最小变更原则。
- 完成后验证。
- 复杂任务：Plan → Execute → Verify → Deliver。
- 目标：低认知负担、低无效 Token、可验证、可执行。

4. Commands

把高频动作变成短指令，不污染全局上下文。

/plan

最小计划

目标 → 步骤 → 风险 → 验证。小任务不要过度规划。

/research

深度研究

优先一手资料；区分事实、推断和假设；最终形成可执行结论。

/debug

根因调试

读取 → 复现/分析 → 根因 → 最小修改 → 验证。

/review

代码审查

检查正确性、边界、回归、异常和无关修改。

/verify

结果验证

尽可能实际执行测试、构建、运行或检查；输出依据。

/html

HTML Artifact

判断 HTML 是否有实际价值；有则直接构建可运行的单文件 Artifact。

5. Skills

Skill 承载专业方法论；不要把这些内容塞进 AGENTS.md。

deep-research

Deep Research

问题定义 → 一手资料 → 交叉验证 → 方案比较 → Gap → 可执行结论。

architecture

Architecture

Goal / Constraints / I/O → Components → Interfaces → Data Flow → Failure Modes → Verification。

industrial-ai

Industrial AI

关注实时性、确定性、安全、恢复、通信边界和可维护性。AI 做理解/规划，确定性系统负责实时执行。

html-artifact

HTML Artifact

优先 SVG + CSS + 原生 JS；单文件、少依赖、可运行、交互有实际意义。

6. Subagents

只建立三个角色，避免 Agent 数量膨胀。

角色职责默认权限
@researcher搜索、阅读、整理、交叉验证、发现技术 Gap只读优先
@reviewer寻找 Bug、遗漏、风险、逻辑矛盾和回归只读
@architect需求、约束、架构、数据流、风险与实施方案先设计，不改代码

7. ZCode × Cursor

共用思想，按工具适配载体。不要维护两套完全不同的方法论。

ZCode

Agent OS 主力执行

全局：AGENTS.md

高频：Commands

复杂流程：Skills

隔离任务：Subagents

Cursor

工程编码与协作

核心：AGENTS.md / Rules

复杂能力：Skills

专用角色：Subagents

项目级规则优先于个人通用规则

维护原则：核心原则只维护一份。工具特有的配置才单独适配。这样未来换 Codex、Claude Code 或其他 Agent 时，不需要重写整个系统。

8. 落地路线

不要一次性做成“超级 Agent OS”。从实际使用中进化。

1

v1.0 · 基础规则

建立短版 AGENTS.md + 6 个 Commands。

2

v1.1 · 高频工作流

根据真实任务，把重复方法沉淀成 4 个 Skills。

3

v1.2 · 专业 Subagents

Researcher / Reviewer / Architect 分离上下文和职责。

4

v2.0 · 自动路由

让 Agent 根据任务复杂度自动选择 Command、Skill、Subagent 和模型。

5

v2.x · 经验沉淀

只把反复出现且长期有效的经验升级为 Rule；避免 Memory 和 Rules 无限膨胀。

10. Definition of Done

Agent 结束任务前的最小检查。

是否真正理解了用户目标？
是否选择了合适的输出媒介？
是否避免了无关修改？
是否完成了必要验证？
是否保留了关键约束？
是否产生了可执行结果？
