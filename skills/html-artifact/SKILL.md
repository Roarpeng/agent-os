# HTML Artifact

## 第一步：价值判断

构建前先回答：交互/可视化是否比 Text/Table/SVG **显著**降低理解成本？

- **适合**：多维数据浏览、方案对比、流程/架构演示、参数模拟（"如果…会怎样"）、小型计算工具。
- **不适合**：静态信息（用 Markdown）、单一代码片段（用代码块）、简单列表（用 Table）。

判断为"不值得"就明确说，并改用更轻的媒介。

## 构建规范

1. **单文件**：CSS/JS 全内联；零构建步骤；无外部网络依赖（CDN/字体/图片一律不用）。
2. **技术选择**：SVG + CSS + 原生 JS 优先；框架（React/Vue 等）仅在组件复杂度确实需要时使用，且内联打包。
3. **交互有实际意义**：筛选、对比、参数模拟、"如果…会怎样"。禁用装饰性动效（自动轮播、无意义动画、粒子背景）。
4. **数据与逻辑分离**：数据内嵌为 `const` 或 `<script type="application/json">`，与渲染逻辑分开，方便更新。
5. **可读性**：深浅色均可读（跟随系统配色变量）；≤768px 不破版；数字用等宽字体对齐。
6. **语义与可访问**：标题层级有意义；交互元素用真实 `<button>`；图表配文字摘要（不只靠颜色传达信息）。

## 构建后验证（必须执行）

- [ ] 打开渲染：无空白、无布局破损
- [ ] 交互测试：每个交互元素实际点一遍
- [ ] 控制台：无错误
- [ ] 数据抽查：渲染结果与源数据抽查一致

## 输出

单个 `.html` 文件 + 一段说明（用途、数据来源与时间、如何打开）。
